# contract/AGENTS.md

The npm workspace package `@app/contract`, private and never published: the API written contract first with oRPC ([ADR 0012](../docs/adr/0012-shared-orpc-contract-in-an-npm-workspace.md)). It also holds `openapi.json`, the generated description of every route under `/api`, its request schema, its success response and its error codes ([ADR 0002](../docs/adr/0002-api-errors-carry-codes-not-copy.md)), never edited by hand.

## The package

```
contract/
├── src/contract.ts            # the contract router: one key per feature, the package's main export
├── src/<feature>.contract.ts  # that feature's procedures, their Zod schemas and the types inferred from them
├── dist/                      # the build the back end imports (ES modules and declarations); never committed
└── openapi.json               # generated by the back end; never edited
```

- **One procedure per route**: `oc.route({ method, path, tags, successStatus })` with the route's method and a path relative to the `/api` prefix the back end sets (`/health`, not `/api/health`), then `.input()`, `.output()` and `.errors({ "<code>": { status } })` with the ADR 0002 codes it can answer. An output object is `z.strictObject`, so the document closes it (`additionalProperties: false`) and `api-docs.spec.ts` catches a field the route sends but the contract does not declare.
- **Imports**: the main export (`@app/contract`) is the router; a file's exports are reached by its path without the extension (`@app/contract/health.contract`). Inside the package, a relative import carries `.js`, as ES modules require. No barrels: `contract.ts` re-exports nothing.
- **Compiled, not source**: `tsc` writes `dist/`, and `package.json`'s `exports` point there, because the back end's Node and Jest cannot run TypeScript from `node_modules`. The root's `setup`, `dev`, `build`, `test`, `typecheck` and `e2e`, CI and both Dockerfiles build it before the apps; `npm run dev` keeps it rebuilding. After pulling or editing it outside `dev`, run `npm run build -w contract`.
- **Dependencies**: every `@orpc/*` package in the workspace is pinned to exactly the same v1 release (1.16.2), in this package and in the apps; the back end documents Zod v4 schemas with `@orpc/zod/zod4`.

## How openapi.json is made

- Until every route is in the contract, the document is two halves merged in `backend/src/docs/api-document.ts`: oRPC's `OpenAPIGenerator` describes the contract's routes (placed under `/api`), and the back end's Swagger decorators describe the rest, as `backend/AGENTS.md` ("Documenting a route") says. Swagger UI serves the same document at `/api/docs`.
- `npm run openapi -w backend` writes `openapi.json`. It needs no database.
- The front end's request and response types are generated from it: `npm run generate:api -w frontend` writes `frontend/src/utils/api/api-types.generated.ts`. The `*-api.ts` modules alias those types; do not hand-write a duplicate.

## Changing the contract

1. Change the procedure here, or for a route not yet moved, the controller, its decorators or the Zod schema in the back end, test first.
2. Run `npm run build -w contract`, `npm run openapi -w backend`, then `npm run generate:api -w frontend`, and fix whatever the typechecks now report.
3. Commit `openapi.json` and the generated types with the change.

A back-end test and the `contract` job in CI fail when `openapi.json` differs from what the back end generates, or the generated types differ from `openapi.json`.
