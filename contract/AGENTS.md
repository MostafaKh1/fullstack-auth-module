# contract/AGENTS.md

The npm workspace package `@app/contract`, private and never published: the API written contract first with oRPC ([ADR 0012](../docs/adr/0012-shared-orpc-contract-in-an-npm-workspace.md)). It also holds `openapi.json`, the description of every route under `/api` generated from it, never edited by hand, and the closed set of error codes and the error envelope ([ADR 0002](../docs/adr/0002-api-errors-carry-codes-not-copy.md)).

## The package

```
contract/
├── src/contract.ts            # the contract router: one key per feature, the package's main export
├── src/<feature>.contract.ts  # that feature's procedures, their Zod schemas and the types inferred from them
├── src/field-rules.ts         # the field rules (email, name, password), one Zod schema per form, their rule ids
├── src/field-rules.examples.ts # the worked-examples table both apps' suites run
├── src/error-envelope.ts      # ERROR_CODES (status, retryable), the envelope's Zod schema and its types
├── dist/                      # the build the back end imports (ES modules and declarations); never committed
└── openapi.json               # generated by the back end; never edited
```

- **One procedure per route**: `oc.route({ method, path, tags, successStatus })` with the route's method and a path relative to the `/api` prefix the back end sets (`/health`, not `/api/health`), then `.input()`, `.output()` and `.errors({ "<code>": { status } })` with the ADR 0002 codes it can answer, those raised before the procedure runs (the body parser, the throttler) included; `request.validation_failed` declares `data: { issues }`. The back end writes each as the envelope and the front end's client decodes it back into that typed error. A date in an output is `z.date()`: the wire carries an ISO string, and the client's type says `string`. An output object is `z.strictObject`, so the document closes it (`additionalProperties: false`) and `api-docs.spec.ts` catches a field the route sends but the contract does not declare.
- **Imports**: the main export (`@app/contract`) is the router; a file's exports are reached by its path without the extension (`@app/contract/health.contract`). Inside the package, a relative import carries `.js`, as ES modules require. No barrels: `contract.ts` re-exports nothing.
- **Compiled, not source**: `tsc` writes `dist/`, and `package.json`'s `exports` point there, because the back end's Node and Jest cannot run TypeScript from `node_modules`. The root's `setup`, `dev`, `build`, `test`, `typecheck` and `e2e`, CI and both Dockerfiles build it before the apps; `npm run dev` keeps it rebuilding. After pulling or editing it outside `dev`, run `npm run build -w contract`.
- **Dependencies**: every `@orpc/*` package in the workspace is pinned to exactly the same v1 release (1.16.2), in this package and in the apps; the back end documents Zod v4 schemas with `@orpc/zod/zod4`.

## How openapi.json is made

- The document is generated only from the contract: `buildOpenApiDocument()` in `backend/src/docs/api-document.ts` runs oRPC's `OpenAPIGenerator` over `contract` and places the paths under `/api`. The error envelope is its `ErrorEnvelope` component (from `error-envelope.ts`), each response names the codes it can carry, and `bearer` and `cookie` security come from the procedures' `spec`. Swagger UI serves the same document at `/api/docs`.
- `npm run openapi -w backend` writes `openapi.json`. It starts no server and needs no database.
- The front end generates nothing from it: its client and its error types come from the contract package itself.

## Changing the contract

1. Change the procedure here, test first.
2. Run `npm run build -w contract` and `npm run openapi -w backend`, and fix whatever the typechecks now report.
3. Commit `openapi.json` with the change.

A back-end test and the `contract` job in CI fail when `openapi.json` differs from what the back end generates, .

## The field rules

- `field-rules.ts` is the one copy of the rules of `docs/requirements.md`; the back end's request schemas and the front end's forms import it. Every check's error is its rule id (ADR 0002); lengths count code points.
- `field-rules.examples.ts` is the worked-examples table. Both suites run every row: add or change a row there, and the two apps are tested against it.
