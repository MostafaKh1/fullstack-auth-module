# e2e/AGENTS.md

The Playwright journeys: the third test seam of [ADR 0004](../docs/adr/0004-quality-gates-and-test-seams.md). A real Chromium drives the real front end and back end over a real MongoDB, to catch drift between the apps (paths, cookie scope, the proxy, CORS), not edge cases. A workspace of its own in the root npm workspace ([ADR 0012](../docs/adr/0012-shared-orpc-contract-in-an-npm-workspace.md)), holding no application code.

- **Run**: `npm ci` at the root, `npx playwright install chromium` in this folder once, then `npm run e2e` from the root, which builds the contract package first (or `npm test` here once it is built). `playwright.config.ts` starts both apps on ports 3100 and 5174, so it never meets the development servers.
- **The database**: `E2E_MONGODB_URI` if set (CI's `mongo:8.2.6` service container); otherwise `support/start-backend.mjs` starts a throwaway `mongodb-memory-server`, so no Docker is needed locally. It starts the API with the Node arguments in `backend/node-register-args.json` (`--import ./register-ts.mjs`: ts-node for ES modules and the `@/` alias), the file the back end's `configuration.spec.ts` reads too; the back end's `dev`, `openapi` and `openapi:check` scripts repeat them, since a package script cannot read a file.
- **A new journey** goes in `tests/`, one file per area, with a fresh email address per run (the database is not reset). Locate by role and label, assert with web-first `expect`, never sleep. Add a journey only for a path that crosses both apps.
- **Containers**: the root `compose.yaml` runs the whole stack (`docker compose up --build` with `JWT_ACCESS_SECRET` and `MONGO_PASSWORD` set, as the README shows, then http://localhost:8080); CI builds both images and waits for every health check.
